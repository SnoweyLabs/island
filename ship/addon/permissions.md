# Permissions and why

One sentence for each permission the manifest asks for. The test `ExtensionGuardTests.The_Manifest_Asks_For_Only_The_Permissions_Some_Code_Uses_And_Carries_The_Addons_Own_Version` checks that each one is used by some code of the add-on; a permission no code uses would be removed from the manifest. None was unused, so none was removed.

- **tabs** — to read each tab's title and the host of its address (never the full address) and to switch to a tab or **close** one when Island asks, so that Island can show, switch and close the person's tabs. (`chrome.tabs`, in `background.js`.)
- **favicon** — to read the small picture the browser has already stored for a tab's site, from the browser's own cache, so that Island can draw it on the tab's tile; it is never asked of any website. (`/_favicon/`, in `background.js`.)
- **alarms** — to try to reconnect to Island every 30 seconds, quietly, when Island was not running yet; the browser would otherwise put the add-on's background worker to sleep. (`chrome.alarms`, in `background.js`.)
- **storage** — to keep one invented identifier in the browser's own storage, so that Island can tell several browsers or profiles apart. It contains nothing about the person. (`chrome.storage.local`, in `background.js`.)
- **scripting** — to put the add-on's own script files into a tab on one of the five media sites that was already open when the add-on was installed, updated or reloaded, so that the person does not have to reload the tab; it is used once at those moments and when the browser starts, never on a timer. It puts in the same files the manifest already lists for those sites, files of the add-on only, never text or code from anywhere else, and never on any other site. (`chrome.scripting`, in `background.js`.)
- **Host permissions on the five sites** (`www.youtube.com`, `music.youtube.com`, `www.twitch.tv`, `soundcloud.com`, `open.spotify.com`) — the same five addresses the content scripts below run on, and no others: Chrome requires host access to a site before an add-on may put a script into a tab of it. Nothing is fetched from them.
- **Host permission `http://127.0.0.1/*`** — the one address the add-on talks to (Island, which listens on this same computer only). **UNVERIFIED:** whether this host permission is needed at all for a WebSocket connection to that address: no page that was opened says it is, and the add-on makes no other request to it. It was kept because the add-on has never been run in a real browser and removing it could break the one connection it exists for; the owner may ask Claude to try removing it in a real browser.
- **Content scripts on five sites** (`www.youtube.com`, `music.youtube.com`, `www.twitch.tv`, `soundcloud.com`, `open.spotify.com`) — to read what the page's player is playing (title, artist, position, length, state) and to press the player's play, pause, next and previous buttons when Island asks. They run on those five sites only. One of the two scripts runs in the page's own world, because only there can the page's player be read; to do that it **wraps two functions of the page** (the page's own setter of media-session handlers, and the play function of media elements) so that it can remember the handlers and the element the page uses, then calls the originals unchanged. It reads, presses the player's buttons when Island asks, and receives no code from anywhere. **UNVERIFIED:** none of the five sites was opened while it was written, so the way it finds each player and each button is a guess that may not work on the real sites.

No other permission is asked: no cookies, no history, no bookmarks, no downloads, no broad host access.
