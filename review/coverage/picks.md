## How to read this

- **Kind** is one of PROVED (a unit test or a self-test check that would go red if the promise broke, found by name), NO PROOF, PERSON ONLY, REPLACED.
- A unit test is written `Class.Method` and lives in `Island.Tests` (the only project that holds these tests; the Attack projects are not cited). Where one class name is used twice in
  `Island.Tests` the file is given. A self-test check is written as the stage file in square brackets followed by the quoted text, the text copied from its `report.Check("...")` (an escaped quote is left as `\"`).
- Where an old document names a test by a name that no longer exists but the same test exists under another class name, the row cites the real name and says so ("EVALS names
  `X.Y`; found as `Z.Y`"). The main session must keep that in mind for `CoverageTests`: the real name is the one that is in the code.
- A self-test check that reads "... or foregroundGranted: false" passes without proving anything when Windows refuses the foreground (it happens whenever Dan is using the laptop). Those rows
  are PROVED on the logic side (the unit tests) and the foreground half is listed in STATE.md "NEEDS-HUMAN-VERIFY" (cited in the row).
- A "Done means" row is PROVED when everything the section names (its tests, its self-test paragraph) exists and fits; what it leaves to a person is cited, not counted separately. A promise
  that is written inside a section but is not a Done means, a named test or an EVALS item is not a row: those are in "Further gaps" at the end (numbered G1...), each with its smallest test.
- Sections of the work orders that belong to the other three areas are not rows here (WO1 section 3 to 5 and 7, WO2 section 3, WO3 section 2/4/5, WO4 section 2, WO5 section 1 and 7, WO6 section 1/2/6,
  WO7 section 1 to 4, WO9, WO10 section 1, WO11 section 2 to 5, WO12 section 1/3). Borderline sections taken here: WO3 section 6 (Folders page), WO6 section 3 (start with Windows, a switch in Settings)
  and section 5 (the X button acts on a pick), WO8 SETTINGS_FROM_NEWER_VERSION (the settings file; the updates auditor has the rest of WO8 section 1).
- Test run of the audited tree: `dotnet test tests\Island.Tests` gave 1677 passed, 1 failed, 0 skipped. The failure is `ExtensionGuardTests.The_Zip_Holds_The_Addon_Without_Its_Tests_Its_Protocol_And_Its_Readme`
  (it compares the committed `ship/addon/island-addon.zip` with the `extension/` files byte for byte; the failure message shows 13 10 expected against 10 in the zip, i.e. this worktree's checkout turned the line endings of an `extension/` file into CRLF while the zip holds LF; most likely a worktree artifact and UNVERIFIED in the main folder): not in this area, and not a finding about the picks code.

## Most important gaps

1. **A broken `pages.json`, `picks.json` or `scenes.json` is never said out loud** (P7, SETTINGS_UNREADABLE): `AppHost.Start` writes a log line and nothing else, so a broken picks file shows an empty
   island with no word; only a broken `settings.json` (and a newer-version file) raises a notice, and no test or check covers even that path (also WO1 HOTKEY_TAKEN at start-up, WO8
   SETTINGS_FROM_NEWER_VERSION). One self-test check per file, reading `AppHost.LastRefusalCode`, closes the proof; the missing words are a likely defect for the main session to classify.
2. **"Run the setup again ... changes only what the person touches"** (WO7 section 6) is proved by a test whose key step is an empty loop; and **"the idle time does not run while a tile is lifted / the
   pointer is over the open second row / the wheel and arrows reset it"** (WO4/WO5, G2) has no test at all.
3. **Rows that are about what Settings shows** are only ever drawn, never read back: one row per action (K1), the island's key list (G3), the TERMINALS_PAGE_NO_ROOM line, the Scenes tray menu and its
   delete question (G4), and the rim of a page Dan made himself (P3). A walker over the built `SettingsView` (the stages already have `TextOfId` and `CountTextContaining`) would prove them together.
