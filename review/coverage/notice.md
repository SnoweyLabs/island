## How to read this

- **Kind** is one of: `proved` (a test or a self-test check that goes red if the promise breaks), `NO PROOF`, `PERSON ONLY`, `REPLACED`.
- A unit test is written as the project name in backticks, a slash, then the class and method in backticks (for example the project `Island.Tests` and the test `NoticeTests.A_Newer_Notice_Replaces_The_Older`), as found by grep in `tests/`. A self-test check is written as the exact text of its `report.Check("...")`, found in a `src\Island.App\*Stage.cs` file, in backticks. Where a check's text holds `\"` it is copied as the source has it.
- "Where written" gives the file and an anchor (a heading or a verbatim phrase), never a line number.
- A name that the work order gives and that I did not find is not a proof. Where the same promise is proved under another name, the row says so and names the proof I found.
- Strictness: "the code does it" is not a proof. A test that exists but pins something other than the promise is `NO PROOF` with the reason.
- For every `NO PROOF` row the last column holds the smallest test that would prove it.
- Rows are one per item. Sub-promises found inside prose, which the documents do not name as a test, are in the appendix "Further unproved promises noticed" (not counted).
