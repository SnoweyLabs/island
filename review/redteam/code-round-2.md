## 2. The findings

### MEDIUM

**code-2-1 - the repair of code-1-16 refuses a name that is already saved, and with it the whole file.** `src/Island.Core/Picks/Pick.cs`, `IsStorable`: b34a7d5 added `if (BlankText.HasBrokenCharacter(Name)) return Fail("name holds a half character")`. `HasBrokenCharacter` is "the text holds U+FFFD" (a lone surrogate reads as U+FFFD, so it cannot tell a lone surrogate from a real U+FFFD, and a real one saves and loads as itself). `IsStorable` is not only the gate of adding: it is the check `PickStore.TryReadPick` runs on every pick it LOADS, the guard of `PickStore.Save` (`Picks.Any(p => !p.IsStorable ...) return false`), the guard of `PickStore.Move`, and, through `SceneStore.TryReadThings` ("the one reader of picks is PickStore's"), of every thing in `scenes.json`. A name with U+FFFD in a file the last build wrote is exactly what the old code made of a lone surrogate (a folder or file name Windows allows to hold one), and a mis-encoded folder or program name can carry a real U+FFFD.
What the person meets: `picks.json` (or `scenes.json`) is Unreadable for ONE such name: "A pick is not valid: name holds a half character." The island starts with no picks (or no scenes), the file is left as it is (nothing deleted), every Settings change to the picks says "could not be saved", until the file is edited by hand. If such a pick gets in memory by another way, `Save` of the whole list is refused. And a folder or file whose OWN name holds the character (the name of a hand-made pick is the leaf of the path, which the person cannot edit first) can no longer be put on the island at all: "That could not be added: name holds a half character." with no way out.
Tests (red): `Round2NameTests.Defect_PickStore_One_Saved_Name_With_A_Replacement_Character_Makes_The_Whole_Picks_File_Unreadable` ("Unreadable: A pick is not valid: name holds a half character"), `...Defect_PickStore_Save_Refuses_The_Whole_List_When_One_Pick_That_Was_Loaded_Holds_A_Replacement_Character`, `...Defect_SceneStore_One_Saved_Thing_Whose_Name_Holds_A_Replacement_Character_Makes_Every_Scene_Unreadable` ("A scene has a thing that is not valid"), `...Defect_HandPicks_A_Folder_Whose_Own_Name_Holds_A_Replacement_Character_Cannot_Be_Added_At_All`. ### LOW

**code-2-2 - the newest emoji are "unassigned".** `BlankText.HasHiddenCharacters` refuses `UnicodeCategory.OtherNotAssigned`, read from the .NET runtime's own table (here 10.0.12; U+1FAE9 of Unicode 16 is known). Emoji 17.0 (Sept 2025; unicode.org's `emoji-data.txt` lists `1FACD orca`, `1FAC8 hairy creature`, `1FAEF fight cloud`, `1FA8A trombone` as E17.0) are `OtherNotAssigned` to it. A page named `Orca <U+1FACD>` is refused with "A page name can hold letters, digits and ordinary punctuation, but no hidden or control characters." although it draws (and has since WO7 for scenes; the repair of 1-16 carried it to pages). It will happen more as Unicode grows past the runtime. Test: `Round2NameTests.Defect_PageStore_Refuses_A_Name_That_Holds_An_Emoji_Added_To_Unicode_After_The_Runtime_Was_Built` (it first asserts the premise: the runtime calls U+1FACD unassigned). Smallest repair: drop `OtherNotAssigned` from the rule: an unassigned code point draws as a box, it is visible; the rule's reason (a name that says nothing or something else) names format, control, private-use and U+FFFD.

**code-2-3 - an emoji joined by a joiner is "hidden".** `U+1F468 U+200D U+1F4BB` (one picture) holds U+200D, category Format, and is refused with the same "hidden or control characters" for a page name (and a scene name). The same for every family, couple, profession and rainbow-flag emoji, and for the zero-width non-joiner that Persian, Kurdish and Hindi spelling needs. The person sees nothing hidden. Test: `Round2NameTests.Defect_PageStore_Refuses_An_Emoji_Sequence_Joined_By_A_Zero_Width_Joiner_As_A_Hidden_Character`; `The_Right_To_Left_Override_And_A_Name_That_Draws_As_Nothing_Are_Still_Refused` (passes) shows what the rule is for. Smallest repair: allow U+200C and U+200D (and tag characters) between two characters that draw; keep refusing U+202A to U+202E, U+2066 to U+2069, U+200B, U+FEFF and the rest. This is the rule scenes had since WO7, so the main session may take it as a proposal.

**code-2-4 - the half of "the rule scenes keep" that was not carried.** `SceneStore.CheckName` compares names after `NormalizationForm.FormC` ("names that draw the same are the same"); `PageStore.CheckName` compares the raw text. `Caf<U+00E9>` and `Cafe<U+0301>` (the second is what a name pasted from a Mac file is) are two pages that look the same in the strip, in Settings and in the key list. Test: `Round2NameTests.Defect_PageStore_Two_Names_That_Draw_The_Same_Through_Canonical_Equivalence_Are_Two_Pages`. Smallest repair: compare `Normalize(FormC)` in the `clash` line (and in the load's `Two pages have the same name`).

**code-2-5 - a ghost chip on the next page with the same id.** `SettingsSession._switchedOff` keeps a switched-off hand-added pick with its `PageId`; `PickRows(pageId)` adds the kept picks of that id that are not in the store. `PageStore.NextId` hands out the first free `page-N`, so after `DeletePage("page-1")` (the person confirmed "your picks on this page will be removed") the next `CreatePage` is `page-1` again, and the new empty page shows the faint chip of a pick that went with the old page; switching it on puts it back on the wrong page. Test: `Round2SessionTests.Defect_A_Switched_Off_Pick_Of_A_Deleted_Page_Shows_Again_On_The_Next_Page_That_Gets_The_Same_Id`. By reading, the same list keeps a chip across "Bring back the starter list" for its page (the question says the picks "will be replaced"); not tested. Smallest repair: `_switchedOff.RemoveAll(p => p.PageId == id)` in `DeletePage` (and in `RestorePage` for that page).

**code-2-6 - the repair of 1-4 and 1-5 covers the move, not the write.** `AtomicFile.Write` calls `File.WriteAllText(temp, text)` before its `try`; only a failed move deletes the temporary file. A write that fails part way (a full disk, a quota, a failing drive, a program that blocks the write) leaves `settings.json.tmp` (or pages, picks, scenes) with whatever part of the refused list was written: the thing 1-4 was about. A disk-full is not made here; the test stands in for any failure of the write with a text UTF-8 cannot encode (`File.WriteAllText` throws `EncoderFallbackException`, an `ArgumentException`, which the stores' `Save` also catches; `ToJson` never makes such a text). Test: `Round2FileTests.Defect_AtomicFile_A_Write_That_Fails_Part_Way_Through_The_Temporary_File_Leaves_It_Behind`. Smallest repair: put `File.WriteAllText(temp, text)` inside the existing `try`.

**code-2-7 - by reading and Learn: the failure path can delete the only copy.** `AtomicFile.Write` uses `File.Replace(temp, path, null, ...)` when the live file exists. Learn (`ReplaceFileW`): on `ERROR_UNABLE_TO_MOVE_REPLACEMENT` (1176) with no backup name, "the replaced file no longer exists and the replacement file exists under its original name". The next attempt takes the `File.Move(temp, path)` branch and normally succeeds; if the six attempts all fail, the `catch` deletes `temp`: then neither file exists, and the next start reads `settings.json` as missing (defaults), `pages.json` as missing (the custom pages gone) and `picks.json` as missing (the starter picks are applied: every hand-made pick gone). Needs a 1176 and five more failures in a row (a program that keeps the name from being created for a quarter of a second): very unlikely; not reproduced (cannot be made without a driver). Smallest repair: in the `catch`, delete `temp` only when `File.Exists(path)`. Same hardening: pass a backup name (`path + ".bak"`) so the replaced file is never lost.

**code-2-8 - the icon retry has a ceiling and a trigger.** `IconMisses`: `MaxTries = 3`, 20 s apart. After the third miss `ShouldRetry` is false for ever (test `IconMisses_Asks_Again_Twice_After_The_First_Miss_At_Most_Once_At_A_Time_And_Then_Never`, which is the statement): a hand-made place on a network drive that is off for the first minute (a VPN that connects late) keeps its two letters until Island restarts, which was the symptom of code-1-13, now bounded to the first minute of the run. By reading: the retry is asked only when `IconCache.Get` / `TerminalsPage.IconOf` / `SecondRow.IconOf` run, and `PickPages.ItemsOf` caches each page's items until `Invalidate()`; UNVERIFIED how often the page is invalidated when nothing opens or closes. Smallest repair: no `MaxTries`, a longer wait each time (20 s, 1 min, 5 min, then every 5 min). A proposal if the main session wants the bound.

**code-2-9 - the throttle has a memory of one line.** `LogThrottle.ShouldWrite` suppresses a line equal to the one written just before. Two alternating lines (an error logged from two places on every frame, or one whose text holds a changing number) are all written: 1,000 of 1,000 in `LogThrottle_Remembers_One_Line_Only_So_Two_Lines_That_Alternate_Are_Both_Written_Every_Time` (a statement). The disk is bounded by the 512 KB rotation (one `.old`), but each line is a `FileInfo` and an open-append-close at the frame rate. Smallest repair: remember the last few lines (a small dictionary of line to time), or count by the exception type.

**code-2-10 - by reading, UNVERIFIED: `Hide` is not guarded.** The repair of 1-18(d) wrapped `Show` and `Follow` in `catch (COMException) -> Lose`. `MovingLight.Hide()` calls `StopRamps()` and `StopAnimation("Opacity")` (compositor calls) and then hides the two windows; `Dispose` calls `TearDown`. If a compositor call throws after a device loss, `Hide` leaves before `GlassWindow.Hide(...)`: the two light windows stay on screen after the island has gone. Whether those calls can throw is not on Learn; not made here (no `MovingLight` may be created). Smallest repair: the same `try`/`catch (COMException) { Lose(e) }` round `Hide`, and hide the two windows first.
