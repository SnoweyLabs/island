## 2. Findings

**ease-4-1 (LOW) - the scene note is not told.** `IslandController.DescribeForScreenReader` and the key it keeps. The repair of ease-3-5 (3e7ec3d) tells `PendingDeleteId`; the scene note is still only in `ContentsLayer` (`SetSceneNote`), reached by `IslandController.ShowSceneNote` from `IslandRuntime.RunScene`. After a scene's key the island comes in without the keyboard and draws the scene's name and "3 opened"; the words say the page and the selected tile. A person who cannot see the island is told nothing of the result of the key he pressed, and nothing if fewer things opened than the scene holds. The other note ease-3-5 named (a close that is refused, "runs as administrator") is mouse-only: the X has no key (WORK-ORDER-10, line 78: "The X button on the island has no key"), so it is not a keyboard finding. Smallest repair: keep the scene name and count in the controller (`ShowSceneNote` sets two fields, `SetSelected`'s reset clears them) and put them in the key and the words (", Mix, 3 opened").

**ease-4-2 - the limit counts code points, the text says characters.** `BlankText.CountCharacters` (`EnumerateRunes().Count()`, bf24c4d). It repaired thirteen plain emoji; a flag is two regional indicators, a thumb with a skin tone two code points, a family emoji five: thirteen flags are 26 and are refused with "A page name can have at most 24 characters." (`PageStore.CheckName`; the same for `SceneStore.CheckName`, test with thumbs). `Round4ElementTests` shows the runtime counts each of these as ONE text element (`StringInfo.LengthInTextElements` = 1; `ParseCombiningCharacters` = one start), which is what the search field's cut now uses (design-3-4). Smallest repair: `CountCharacters` = `new StringInfo(text).LengthInTextElements`; the boxes' `MaxLength` of 64 UTF-16 units already bounds the length, and the load check in `PageStore.Parse` uses the same function. If a limit in text elements is not wanted, the text must say what it counts ("24 letters, signs or emoji, counted by code point").

**ease-4-3 - lookalike names that are two names.** `BlankText.SameName` strips U+200C and U+200D only. Other characters that draw nothing on their own and are let through as marks (category Mn) do the same trick: U+034F (combining grapheme joiner) in "Wo" + U+034F + "rk", and U+FE0F (the picture selector) on a heart. The test creates "Work" then "Wo\u034Frk" (second accepted) and a heart then a heart with U+FE0F (second accepted). Same family as ease-3-11 (two pages that look and read alike), reached by other input. Smallest repair: `SameName` also removes U+034F, U+FE0E, U+FE0F (the stored name keeps them).

**ease-4-4 - the refusal of ease-3-14 lacks where.** `SettingsText.AlreadyOnTheIsland(name)`: "Beta is already on the island under another name, so this one cannot be switched on again. Its key, if it had one, is gone with it." What happened and why are there; what to do is not: the Add panel's refusal for the same case says "Beta is already on the island, on the page Media." (`SettingsText.AlreadyOnIsland(name, page)`, and the file's own comment says the page is where "it is already on page X" comes from). In the test the faint chip is named "Beta" and the pick that took its place is named "Beta", so "under another name" is false. Smallest repair: the text of the Add panel with the page (`PickStore.Find` gives the other pick; its `PageId` names the page): "Beta is already on the island, on the page Media, so this one cannot be switched on again. Its key, if it had one, is gone with it."

**ease-4-5 - Enter held a moment too long.** `SettingsView.OnPreviewKeyDown`/`Capture`. Enter on a key button clicks on the KeyDown (`Parts.Flat` is a Button); the wait starts; the repeat of that Enter (after about half a second, which is exactly a hand that lifts slowly) arrives while `_capturing` is set and is taken as the key: `KeybindEditor.Capture` refuses a bare Enter (`A_Bare_Enter_Is_Refused_As_A_Key`) and the notice appears before the person has pressed a key (the refusal's words are the generic "That combination cannot be used", and it scrolls into view since 956ac18). Space starts on the KeyUp and is not affected. The source has no `IsRepeat` in that region (the Defect_ test). Smallest repair: in `OnPreviewKeyDown`, `if (_capturing is not null && e.IsRepeat) { e.Handled = true; return; }` (the repeat of a key that was down before the wait started). Not verified with a real key; by the code and by WPF's documented Enter-on-KeyDown for Button (the Defect_ test is a source scan).

**ease-4-6 - Disconnect says "did not connect".** `OutsideAgentConnector.Disconnect` and `OutsideCodexConnector.Disconnect` return `AgentRefusals.HooksFileNotWritten` (bf24c4d): "Claude Code's settings file could not be written, so Island did not connect. ... then press Connect again." A person who pressed "Yes, disconnect" is told he did not connect and to press Connect; the helper is still connected. (`HooksFileUnreadable`, used by Disconnect before, has the same words in the same place; that is older, not a repair.) Smallest repair: a refusal for the other direction, or the Disconnect path wording ("so Island did not disconnect ... then press Disconnect again"), or the neutral "did not change it".

**ease-4-7 - a cause told as a fact.** `AgentRefusals.NotifyNotCopied`: "A hook that is running right now holds the old copy, and a hook lives only a fraction of a second. ... Wait a moment and press Connect again." `OutsideAgentConnector.CopyRefusal` picks it for EVERY failed copy once Island.Notify is beside Island: a read-only or full folder, a refused permission, a virus scanner all end here, and waiting mends none of them. The sibling `HooksFileNotWritten` hedges ("may be read-only or held open"). Smallest repair: "Most often a hook that is running right now holds the old copy (it lives a fraction of a second); a full or read-only folder does the same", and "Wait a moment and press Connect again; if it happens again, check that the folder of Island can be written to."

**ease-4-8 - two rules for one question.** `HandPicks.DropHidden` (bf24c4d, code-3-5) drops every character of category Format from a name taken from a file or folder; U+200D is Format. A folder called with a family emoji becomes a pick named with three separate people (the test prints the runes 1F468 1F469 1F467, no 200D); the joiner that spells a word in Persian or Hindi is cut out. `BlankText.HasHiddenCharacters` (rounds 2 and 3) keeps a joiner between two visible characters for page and scene names. Smallest repair: `DropHidden` keeps U+200C/U+200D where `BlankText.HasHiddenCharacters` would let them stay (or: build the name, ask `HasHiddenCharacters`, drop only when it says yes).

**ease-4-9 - Restore forgets before it knows.** `SettingsSession.RestoreAllKeys` clears `_keysOfSwitchedOff` before the locked and save checks (956ac18). When the settings file cannot be saved the restore is refused ("The new key could not be saved") and nothing is restored, but the key kept for a pick that is switched off is gone; switching the pick on later gives no key and no word. Reach: a pick with a key switched off, the settings file not writable (read-only folder, held open), "Restore the original keys" asked and answered Yes, the file made writable, the pick switched on. Smallest repair: clear the dictionary only when the result is `Ok`.

**ease-4-10 - "Your old key still works" when there was none.** `SettingsText.KeyTakenByAnotherProgram`, `KeyRefusedByWindows`, `KeyNotSaved` (WORK-ORDER-6 register, K6). True for the main key. Since 6 October no page and no pick has a key by default (`FirstStart`, `Settings.Defaults`; `A_Page_Has_No_Key_Until_The_Person_Gives_It_One`), so the first key given to a page or a pick that another program holds, or that Windows refuses (any error but 1409 names the code), or that cannot be saved, is refused with a sentence about an old key that does not exist. It also reaches the new warning of ease-3-8 ("... was not given back. Ctrl+Alt+J is already used by another program. ... Your old key still works."). Smallest repair: `KeybindEditor.Assign` knows `old`; build the second part without the sentence when `old` is null ("Nothing was changed.").

**ease-4-11 (LOW, UNVERIFIED, no test) - the heading's event.** `SettingsView.Rebuild` raises `LiveRegionChanged` on the section's heading from a Loaded-priority callback, through `UIElementAutomationPeer.FromElement(heading)`. Learn (UIElementAutomationPeer.FromElement, read 7 Oct 2026): it returns `null` if the peer was not created by `CreatePeerForElement`. The heading is a new TextBlock at every build, and WPF makes a peer for an element only when something asks. `Round4LayoutTests.A_Heading_Built_By_Continue_Has_No_Peer_Until_Something_Asks_For_One` shows the premise: after `Continue` and a pump to ContextIdle, `FromElement(heading)` is null and `CreatePeerForElement` then makes one. Whether a screen reader that is attached has already walked to the new heading by the time the callback runs I cannot say without one: if it has not, ease-3-13's repair raises nothing, and a section is still never told. (The same holds for the notice line, which is also new at each build: ease-1-16, a proposal.) Smallest repair, risk-free either way: `if (AutomationPeer.ListenerExists(AutomationEvents.LiveRegionChanged)) UIElementAutomationPeer.CreatePeerForElement(heading)?.RaiseAutomationEvent(AutomationEvents.LiveRegionChanged);`. A person with Narrator should confirm: press Continue in the first start and listen for the new section's heading.
