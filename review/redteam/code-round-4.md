## 2. The findings

### LOW

**code-4-1 - what the page store accepts when typed, its loader reads as one name.** `PageStore.CheckName` compares `BlankText.SameName(...)` (joiners out, then FormC) with `OrdinalIgnoreCase`; `PageStore.Parse` (the load at the next start) compares the RAW names with `OrdinalIgnoreCase` and answers "Two pages have the same name." .NET's `OrdinalIgnoreCase` folds U+0345 (Greek combining iota below) to U+0399 (capital iota); FormC joins U+0345 to the letter before it. So alpha + U+0345 and alpha + U+0399 are two names to `CheckName` (accepted together) and one to the loader. Found by a search over every BMP character against 20 base letters (four pairs: alpha, capital alpha, eta, omega); a 60,000-pair random search over 40 awkward pieces finds nothing else. Effect when it happens: `pages.json` is Unreadable, every custom page is out of reach and Settings refuses changes to pages until the file is edited by hand (the round-2 repair of `410d9a2` is where FormC came in; round 3 held it for the accent, Angstrom and Hangul and did not try this pair). Likelihood: a Greek name typed with a combining iota; practically none for Dan. Test (red): `Round4NameFuzzTests.Defect_PageStore_Two_Names_That_Are_Accepted_Together_Are_Read_Back_As_The_Same_Name_And_The_Whole_Pages_File_Is_Unreadable`. Smallest repair: in `CheckName` also refuse when `string.Equals(p.Name, trimmed, OrdinalIgnoreCase)` (what the loader asks), so that what is accepted is read back. (Scenes read a name with the very function that adds it, so they cannot have this: `Held_Random_Scene_Names_That_Are_Accepted_Together_Are_Read_Back`.)
