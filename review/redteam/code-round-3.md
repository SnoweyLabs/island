## 2. The findings

### MEDIUM

**code-3-1 - the next visit is not told again; the repair is in a branch an ordinary hide never takes.** The repair of ease-2-1 (db7c540) put `_describedKey = default; // the next visit is told again` into `IslandController.Draw`, in the branch `if (_machine.Phase == IslandPhase.Hidden) { ...; return; }`. The phase becomes `Hidden` in one place only: `IslandMachine.Tick`, when `Closing` has settled out of sight. The frame that runs it is `Step`: `_machine.Tick(now); ... if (_machine.Phase == IslandPhase.Hidden) { Detach(); return false; }` returns before `Draw` is called, and `Detach` (the one place every hide passes through) does not touch the key. So after an Esc, the idle time or the main key, the key of the last visit stands. At the next summon `Draw` computes the key again: the page, the selected index (reset to the preferred tile on a summon, usually 0), the count and the selected item are the same as at the last visit when the person did not move the selection; `key == _describedKey`, and `Describe` is not called. (`Draw`'s own hidden branch runs only when an input arrives in the one frame between the settle and `Step`'s check, which is not the ordinary way.) A second layer: `IslandHost` makes one `IslandRoot` for the life of the app (`public IslandRoot Root { get; } = new() ...`) and `IslandRoot.Describe` begins with `if (text == _description) return;`, so even a call with the very words of the last visit raises no name change and no live-region event. A person who summons the island again to the same page and the same tile is told nothing at the second and every later visit. What the person sees is unchanged; what a screen reader says is.
Grade: MEDIUM because the repair's own words promise it ("the next visit is told again", and in the commit message "the next visit is always told again") and the case it misses is the commonest one (summon, look, Esc, summon again). UNVERIFIED with a screen reader: whether Narrator announces the island at a summon by the foreground change alone, and whether a live-region event is what it needs; a person with Narrator must look. The code path is proven by the source (the three tests below read it).
Tests (red): `Round3SourceTests.Defect_The_Reset_Of_The_Words_Key_Is_In_Draw_Where_A_Hide_Of_The_Island_Never_Passes`, `Round3SourceTests.Defect_The_Island_Root_Ignores_Words_Equal_To_The_Last_Ones_So_A_Reset_Of_The_Key_Alone_Raises_Nothing` (it also asserts the premise: one root, kept). The green `Held_The_Words_Key_Holds_The_Items_The_Pill_And_The_Notice_So_A_Change_Inside_A_Visit_Is_Told` shows what the repair did achieve.
Smallest repair: in `Detach()` (or in `Step`'s hidden branch) set `_describedKey = default` and tell the root to forget (`IslandRoot.Forget()` setting `_description = Name`, no event), so that the next `Describe` is a change. Keep `Draw`'s own line.
